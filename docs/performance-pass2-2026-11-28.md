## Условия и честное сравнение

Новый базовый замер снят перед изменениями этого прохода: Chromium, 1280×720 CSS px, DPR 1, сид `0a96a85c297395a3`, начальный витраж, 2.5 с стабилизации и 10 с сбора. Это другой размер окна и среда, поэтому сравнивать FPS напрямую с предыдущими 539×600/DPR 1.6 нельзя. Графическая случайность не закреплена сидом игрового маршрута, поэтому число мелких деталей/частиц между перезапусками немного различается.

По последнему основному замеру: draw calls меньше примерно на 6%, треугольников меньше на 14.5%. Улучшение CPU или FPS не подтверждено: FPS ограничен обновлением 60 Гц, а измеренное CPU-время последнего запуска выше первоначального. Это снижение геометрической нагрузки и числа отправок, а не доказанное ускорение игры на данном компьютере. Дополнительное объединение пропсов по умолчанию выключено: экономия вызовов не дала надёжного ускорения и увеличила число обрабатываемых треугольников на границах камеры.

## Что включено

- Непрозрачные Mesh архитектуры ступеней объединяются через THREE.BatchedMesh по материалу, формату атрибутов и родительскому этажу. Отдельные экземпляры сохраняют frustum culling, матрицы и видимость. Подвижные ступени обновляют свою матрицу; геометрия и материалы не упрощаются.
- Оригинальные меши остаются на отдельном слое для коллизий, камера их не рисует повторно. Оба игровых raycaster учитывают этот слой. Копии не считаются дважды в geometry-report. Затенение башни учитывает batchingMatrix, а локальные узоры камня/дерева сохраняют исходные координаты.
- Количество сегментов маленьких подлестничных колец уменьшено с 4×10 до 3×8; у каждого короткого участка каната продольная сегментация 6 → 3, шесть граней по окружности сохранены. Крепления и анимация ветра не меняются.
- У следа дэша без активных точек больше нет пустых загрузок GPU-атрибутов. Для записи цветов, UV и частиц удалены временные массивы; вектор ориентации переиспользуется.
- Возвращение камней к игроку обновляет таблицу длины Bezier через два повторно используемых вектора и прежний массив вместо создания примерно 40 временных точек на каждый активный камень за кадр. Траектория и ускорение сохранены.
- Для новых батчей добавлено освобождение ресурсов без уничтожения общих материалов.

## Проверенный эксперимент, выключенный по умолчанию

`?prop-batches=1` объединяет фоновые пропсы четырёх соседних ступеней в совместимые InstancedMesh. Атлас обложек, контактный градиент и высота каждой ступени сохраняются; подвижные ступени исключены, скрытые экземпляры обнуляются и восстанавливаются. Границы каждого батча вычислены явно. Обычные пропсы продолжают делить общую базовую геометрию.

`?batching-off=1` выключает оба новых вида батчинга для проверки; облегчённая геометрия и сокращение выделений памяти остаются. В обычном режиме включён только BatchedMesh архитектуры.

Не добавлялись Draco/Meshopt/KTX2: у этой сцены процедурная геометрия и Canvas/DataTexture, а не поток GLB/изображений, для которых совет непосредственно применим. DPR уже ограничен; его не снижали. Фоновые эффекты, SSAO и проходы рендера не отключались. Новые LOD не вводились без отдельной проверки силуэтов/переходов.
