# Предметы на забег

`src/run-items.json` — каталог предметов, эффекты, пулы, число вариантов и перебросов. `src/run-items.js` — чистая игровая модель без DOM, Three.js и хранилища. `src/run-item-ui.js` — экран выбора и список полученных предметов. Ввод проходит через общий контекст `runItems`: ниже глобальных действий и настроек, выше обычных меню и геймплея.

## Жизненный цикл

В начале забега `RunItems.reset` получает результат `skillStats` и список постоянных анлоков. Предметы хранятся отдельно от дерева навыков и никогда не записываются в его сохранение. После выбора пересчитываются итоговые `RUN_UPGRADES`; ссылка на объект сохраняется, поэтому существующие способности, движение, урон и лечение видят новые параметры. Перезапуск очищает предметы, очередь наград и возвращает один переброс. Максимальное здоровье увеличивается сразу; «Тёплое ядро» также восстанавливает 20 света.

Плоские прибавки складываются, множители перемножаются. Например, две «Проворные нити» дают ×1,1² к скорости поверх навыков. Предметы не открывают закрытые способности: увеличение дальности дэша начнёт работать после открытия самого дэша.

Игра, вращение башни и симуляция останавливаются на время выбора. Предложения от нескольких сундуков обрабатываются очередью. Награда одного источника не выдаётся дважды. Собранные предметы показываются только в паузе: ряд ромбов над меню, счётчики копий и плавная подсказка по наведению или фокусу. Влево/вправо переключают предметы, вниз возвращает к продолжению игры. Во время геймплея список скрыт.

## Сундуки и пулы

В `src/interactables.json` у каждого тира есть `rewards`. Сейчас все три тира выдают выбор из общего пула:

```json
"rewards": [{"type": "item-choice", "pools": ["starter"]}]
```

Камни по-прежнему поддерживаются, в том числе вместе с выбором:

```json
"rewards": [
  {"type": "gems", "count": [3, 6]},
  {"type": "item-choice", "pools": ["starter"]}
]
```

У ручного размещения сундука можно переопределить `tier` и `rewards`. Если `pools` отсутствует, используются `activePools` из конфига предметов. Пулы объединяются без дублей. Поле `requirements` у предмета или пула задаёт условия; все перечисленные условия должны выполняться:

```json
"requirements": {
  "stats": {"dashEnabled": true, "phaseDistance": {"gt": 0}},
  "skills": [],
  "unlocks": []
}
```

Булевые статы проверяются точно; числовые поддерживают `gt`, `min` и `max`. `skills` и `unlocks` содержат необходимые постоянные ID. Сейчас их поставщик — `progression.state.owned`; для новой системы достаточно передать её список в `reset`. Проверка производится перед предложением, перебросом и самим получением предмета. Старое поле `requires` поддерживается для совместимости.

У обоих бонусов дэша требуется `dashEnabled: true`. У остальных предметов явно проверяется активная числовая характеристика. Пример будущего закрытого пула — `wayfarer`: в `requirements.unlocks` указан `pool.wayfarer`; покупка этого анлока пока не добавлена в дерево.

Пулы должны содержать хотя бы один доступный предмет; неизвестные ID и пустой доступный набор вызывают явную ошибку. Если доступных предметов меньше трёх, показываются все без дублей. Переброс отключён, если заменить варианты нечем. По умолчанию один переброс **на весь забег**, а не на сундук.

`src/chest-rewards.js` разделяет генераторы типизированных наград и потребителей. В `main.js` зарегистрированы потребители `gem` и `item-choice`. Новый вид содержимого добавляется отдельным генератором и обработчиком, без изменения модели сундука или выборщика предметов.

Выбор предметов использует изолированную ветку RNG `run-items / источник / номер переброса`; графические эффекты не влияют на предложения. Одно и то же состояние забега и источник дают одинаковый выбор. Названия и описания извлекаются из JSON в существующие PO-каталоги, оригинал английский, русский — перевод.

## Редкость и удача

У каждого предмета `rarity`: `common`, `uncommon`, `rare`, `legendary`. Цвет, локализуемое название, базовый вес и чувствительность к удаче заданы в `rarities` того же JSON. Обычный сохраняет прежний цвет; остальные — зелёный, синий, яркий оранжевый. Цвет виден на карточке выбора, ромбе в паузе и подсказке.

Сначала выбирается редкость среди доступных предметов, затем предмет внутри неё. Выбор без повторений; недоступные по requirements предметы не участвуют. В пуле `rarityWeights` переопределяет веса редкостей, `itemWeights` — веса отдельных предметов внутри редкости (по умолчанию 1). Нулевой вес исключает вариант. Для нескольких пулов используются средние веса пулов, содержащих доступных кандидатов, без дублирования предметов.

Базовые веса: Common 48, Uncommon 26, Rare 13.35804647, Legendary 12.64195353. Это около 12.64% Legendary на первый слот; шанс хотя бы одного легендарного предложения среди трёх — примерно 33%. Это не гарантия каждого третьего сундука и не шанс автоматически получить предмет. При исчерпании редкости веса перераспределяются. Переброс старается исключать предыдущие варианты, поэтому его шансы зависят от оставшегося состава пула.

Стат `luck` начинается с 0. Множитель веса: `(1 + max(0, luck)/100)^luckPower`. Степени: Common 0, Uncommon 0.5, Rare 1, Legendary 2. При Luck 100 вес Rare удваивается, Legendary увеличивается вчетверо; после нормализации легендарное предложение встречается примерно в 67% сундуков стартового пула. Удача не открывает закрытые предметы и не влияет на визуальный рандом.

В сокровищнице ветка `treasuryLuck`: пять последовательных узлов по +20 Luck, цены 8/20/45/90/180. Итог +100. Используются существующие сохранения, зависимости, расчёт статов и система терминов/PO (`Luck` в категории terms).
