# Игровые термины

Список терминов, привязка к статам и цвета: `src/game-terms.json`. Переводы: `locales/en/terms.po`, `locales/ru/terms.po`; шаблон: `locales/templates/terms.pot`. У каждого термина контекст `term.ID`, поэтому название характеристики не конфликтует с одноимённым навыком или кнопкой.

## Использование

В исходном английском тексте и его PO-переводе сохраняются одинаковые плейсхолдеры:

```text
msgid "{DashDistance} +15%."
msgstr "{DashDistance} +15%."
```

`tr(key, values)` возвращает обычный текст с переведёнными терминами — для заголовков, title, aria-label и текстовых строк. `renderLocalized(element, key, values)` из `src/localized-text.js` выделяет термины цветом и жирным через DOM. Четвёртый аргумент `false` отключает выделение. В PO не нужно писать HTML.

Если параметр называется произвольно, можно передать явную ссылку на термин:

```js
renderLocalized(description, '{name}: {count}', {name: term('Dash'), count: 2});
```

`term` экспортируется из `src/i18n.js`. Доступны точные ID (`Dash`, `Damage`, `Light`, `MovementSpeed`) и их варианты целиком в нижнем регистре. Лучше использовать точный ID, чтобы отличать термин от числового параметра. Явно переданный параметр всегда имеет приоритет: `{damage}` с `{damage: 12}` остаётся числом, а не словом «Урон». Неизвестные плейсхолдеры остаются видимыми, неизвестный ID в `term()` вызывает ошибку.

Для склонений и специальных форм добавляется отдельный термин в словарь с собственным PO-контекстом. Автоматического склонения и поиска слов регулярными выражениями нет. Тексты локализации и параметры вставляются только как текстовые узлы; теги не исполняются.

При добавлении термина: `npm run locales:update`, заполнить `terms.po`, затем `npm run locales:compile`. Описания предметов, основные описания статов в дереве и игровые подсказки уже используют этот механизм. Новым экранам достаточно подключить `renderLocalized`.
